Architecture

System Overview

ReqManTool follows a clean layered architecture with clear separation of concerns.

┌─────────────────┐     REST + WebSocket      ┌────────────────────┐
│   Frontend      │ ◀──────────────────────▶ │   Backend          │
│   (React/Vite)  │   JSON-RPC 2.0 + REST    │   (FastAPI)        │
└─────────────────┘                            └────────┬───────────┘
                                                       │
                                              ┌────────▼────────┐
                                              │ Data Directory  │
                                              │ (JSON + Git)    │
                                              └─────────────────┘

Layer Responsibilities

Key Design Decisions

Dual Transport Parity

Both REST and WebSocket JSON-RPC call the exact same ProjectService methods. Identical error mapping ensures identical behavior.

Atomic Persistence

Every write uses a temporary file + fsync/F_FULLFSYNC + atomic os.replace. Multi-file operations use a staging directory (.reqman-staging/<random>/) and a single os.rename.

Git-Backed History

Each project is a git repository. Every mutation auto-commits with squashing (10-min window). Baselines are annotated tags + fast-forward baseline branch.

Deterministic Outputs

Reports, exports, and ID allocation are fully deterministic. Same input → same output, enabling independent verification (T2 requirement).
